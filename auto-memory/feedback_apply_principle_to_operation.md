When the work *is* a structural principle (Coherence Principle, perspectival idealism, separation of concerns), the operation that produces the work should also embody it. The repo reorganization (April 16, 2026) made the directory tree itself an instance of the Coherence Principle: five top-level dirs operating on separate degrees of freedom (Library / Technical-Work / Foundations-of-Identity / Research / Unreleased-Work). Clayton said: *"I feel like this is so much more representative of the work that we do, and it will be so much easier to keep things organized if we're applying this principle to our own operation."*

**Why:** When the operation embodies the principle, the principle stays load-bearing rather than ornamental. It also becomes self-evident to anyone who looks at the work: the structure says what the work is. And it makes future organization decisions trivial — "where does this go?" is answered by which DOF it belongs on.

**How to apply:** When organizing anything (repo, palace, memory, daily routine, communication channels), ask first whether the principle of the current work suggests a natural separation. Default to embodying the principle in the operation, not just describing it. This is a generalizable preference — applies beyond the Corpus repo to skills, palace layout, project structure, schedule design, etc.
